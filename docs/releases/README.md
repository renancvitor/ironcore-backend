## Regra de Manutenção

- Não sobrescrever documentação de release anterior.
- Criar uma nova pasta por release somente depois de haver fechamento público ou técnico relevante.
- Manter o README principal do projeto como visão geral; detalhes técnicos devem ficar nos documentos de release ou nos módulos dentro de `docs/`.
- Milestones do GitHub podem ter numeração própria e representar entregas menores. A release documentada pode consolidar um ou mais milestones.
